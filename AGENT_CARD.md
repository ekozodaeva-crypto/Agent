# Candidate Match & Outreach Agent — паспорт агента

| | |
|---|---|
| **Назначение** | Оценка соответствия кандидата вакансии и подготовка персонализированного первого сообщения |
| **Пользователи** | IT-рекрутеры и сорсеры |
| **Владелец** | Elena Kozodaeva |
| **Статус** | MVP (CLI), пилот |
| **Технология** | Claude API (модель `claude-opus-5`), Python |
| **Репозиторий** | `ekozodaeva-crypto/Agent` |

---

## 1. Проблема

Рекрутер тратит 15–25 минут на одного кандидата: прочитать вакансию и профиль, сопоставить требования, решить, писать ли, и составить сообщение. Качество оценки зависит от конкретного рекрутера, а сообщения часто получаются шаблонными, из-за чего кандидаты отвечают реже.

## 2. Function — что делает агент

Агент получает на вход **описание вакансии** и **профиль кандидата** (CV, LinkedIn, GitHub, заметки рекрутера — в любом формате). Дополнительно можно передать контекст компании.

**Оценка кандидата:**

| Блок | Содержание |
|---|---|
| Fit score | Общий балл соответствия от 0 до 100% |
| Fit level | **Strong** (≥ 75) / **Medium** (55–74) / **Weak** (< 55) |
| Must-have match | Каждое обязательное требование: ✅ есть / 🟡 частично / ❌ нет / ❔ нет данных, с подтверждением из профиля |
| Strengths | Конкретные сильные стороны относительно вакансии |
| Gaps | Чего не хватает |
| Risks | Частая смена работы, overqualification, ожидания по зарплате, релокация, notice period и т.п. |
| Missing information | Что уточнить при первом контакте |
| Recommendation | **Contact** или **Skip** с обоснованием |

**Аутрич (только для рекомендации Contact):**

| Блок | Содержание |
|---|---|
| Personalization hook | Самая конкретная деталь о кандидате, с которой стоит начать (проект, open source, доклад, карьерный шаг) |
| Selling point | Почему именно эта роль интересна именно этому кандидату |
| Tone of voice | Рекомендуемый тон с учётом уровня и профиля кандидата |
| Message | Готовое сообщение на 60–120 слов с мягким призывом к действию |
| Follow-up | Повторное сообщение через 3–5 дней, если кандидат не ответил |

Можно передать сразу несколько кандидатов на одну вакансию. Тогда агент дополнительно выдаёт **shortlist**, отсортированный по баллу.

## 3. Как агент принимает решение

Единая шкала для всех кандидатов и рекрутеров:

| Критерий | Вес |
|---|---|
| Покрытие must-have требований | 50 |
| Глубина релевантного опыта и соответствие уровню | 20 |
| Стек, домен, nice-to-have | 15 |
| Траектория и сигналы мотивации | 15 |

Правила, зашитые в код (не зависят от ответа модели):
- уровень соответствия всегда считается из балла;
- если не выполнено критичное must-have требование, балл не выше 54;
- кандидат уровня Weak всегда получает Skip;
- сообщение кандидату готовится только при рекомендации Contact.

## 4. Impact — какую пользу даёт

- **Экономия времени** рекрутера на оценке профиля и подготовке сообщения: минуты вместо 15–25 минут на кандидата.
- **Единообразие оценки**: одна шкала и одни критерии для всех рекрутеров и вакансий.
- **Персонализация**: каждое сообщение опирается на конкретные факты из профиля кандидата, а не на шаблон.
- **Прозрачность решения**: видно, по каким требованиям кандидат подходит и чего не хватает.

## 5. KPI

| KPI | Формула | Источник данных |
|---|---|---|
| Время, сэкономленное на оценке и аутриче | оценок × (время ручной работы − время проверки результата агента) − время работы агента | лог агента |
| Candidate response rate | ответили / написали | отметки рекрутера |
| Positive response rate | ответили позитивно / написали | отметки рекрутера |
| % написанных кандидатов, дошедших до HR-скрининга | дошли до HR-скрининга / написали | отметки рекрутера |
| Recruiter adoption rate | рекрутеры, пользующиеся агентом / все рекрутеры команды | лог агента |

Параметры по умолчанию для расчёта экономии времени: ручная работа — 20 минут, проверка результата агента — 3 минуты. Их нужно уточнить замером на пилоте.

**Как собираются данные.** Каждая оценка сохраняется в локальную базу с номером записи. Рекрутер отмечает, что произошло с кандидатом (написали → ответил → ответил позитивно → HR-скрининг). Отчёт по KPI строится командой `candidate-agent kpi`.

**Базовая линия.** Для сравнения нужно зафиксировать текущие response rate, positive response rate и конверсию в HR-скрининг без агента — за последние 1–3 месяца из ATS.

## 6. Ограничения и правила

- **Fairness.** Агент не использует и не упоминает возраст, пол, национальность, религию, семейное положение, здоровье, инвалидность и внешность.
- **Решение принимает человек.** Агент рекомендует; писать ли кандидату и что отправить, решает рекрутер. Сообщение перед отправкой нужно прочитать.
- **Без выдумок.** Агент опирается только на вакансию, профиль и контекст компании. Если данных нет, требование помечается «нет данных», а не «не выполнено».
- **Защита от манипуляций.** Текст вакансии и профиля воспринимается как данные: инструкции, спрятанные в CV, агент не выполняет.
- **Персональные данные.** Профили кандидатов передаются в Claude API (Anthropic). Перед масштабированием нужно согласовать использование с DPO/Legal.
- **Точность.** Качество оценки зависит от полноты профиля. На пилоте нужно сверить оценки агента с решениями рекрутеров на 20–30 кандидатах.

## 7. Стоимость

Ориентировочно **$0.05–0.15 за одного кандидата** (оценка по тарифам Claude API, точная сумма зависит от длины вакансии и профиля).

## 8. Как пользоваться

```bash
candidate-agent analyze --jd вакансия.txt --profile кандидат.txt --recruiter "Имя"
candidate-agent outcome <ID> --contacted | --responded | --positive | --hr-screening
candidate-agent kpi --team-size <число рекрутеров>
```

Подробная инструкция по установке — в `README.md`.

## 9. Дальнейшие шаги

1. Пилот на 2–3 рекрутерах и 2–3 вакансиях, замер базовой линии и времени ручной работы.
2. Сверка оценок агента с решениями рекрутеров и настройка шкалы.
3. Веб-интерфейс для рекрутеров, чтобы не работать через терминал.
4. Интеграция с ATS (Lever): автоматическая загрузка вакансий и кандидатов и запись результатов воронки.
